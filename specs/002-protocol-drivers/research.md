# Research: Wire Protocols and Datatype-Aware Drivers

**Feature**: `002-protocol-drivers` | **Date**: 2026-09-13

Each item resolves a Technical Context unknown or a technology choice. Format: Decision / Rationale / Alternatives considered. Inputs: [spec.md](spec.md) (incl. Clarifications 2026-09-13), constitution v1.0.0, feature `001` plan/research/data-model (entrypoint model, `Handler` trait, config grammar, admin token seam, buffer registry), intents `03`/`05`/`07`/`08` for the seams this feature must leave open, and the local Rust 1.87 toolchain. Constraint on every choice: **pure Rust dependency set** (Principle I) — no `*-sys` crates wrapping C/C++.

## R1. Sequencing against unspecified sibling features (`03`, `05`, `07`)

- **Decision**: This feature defines and ships three **seams** as Rust traits plus an interim implementation of each, so drivers are buildable and conformance-testable now and the sibling features replace the implementation without touching drivers:
  1. `spacestorage-types` — the **abstract datatype interface** (`TypeRegistry`, `Datatype`, `Container`, `CanonicalValue`) with an interim in-memory inventory of six types (`kv_collection`, `relational_table`, `document_store`, `object_collection`, `vector_collection`, `ordered_map`). Feature `03` owns the full L0–L4 inventory and persistence and will grow the registry.
  2. `spacestorage-exec` — the **execution boundary** (`QueryEngine` trait taking a protocol-neutral `LogicalRequest` + `QueryOptions`) with an interim `LocalEngine` that executes single-node against the type registry. Feature `05` replaces `LocalEngine` with the distributed parser/planner/executor behind the same trait.
  3. `spacestorage-auth` — the **principal/namespace resolver** (`Authenticator` trait: credential → `Principal { name, namespace, schema, roles }`) with an interim `UsersFile` implementation (`auth { users_file }`), mirroring `001`'s `admin { token_file }` seam. Feature `07` replaces it with the cluster role store.
- **Rationale**: Spec FR-011/FR-012/FR-035 require drivers to go *only* through an abstract interface and a shared execution layer; without a concrete trait there is nothing to code against. Making the interim implementations swappable keeps `02` honest to "drivers never own types or engines" while not blocking on three unspecified features.
- **Alternatives considered**: Blocking `02` until `03`/`05`/`07` are specified (rejected: the intent README orders `02` before them and the seams are needed by them anyway); letting each driver embed a minimal engine (rejected: exactly the protocol-private engine FR-035 forbids).

## R2. PostgreSQL wire protocol

- **Decision**: `pgwire` crate (pure Rust, Tokio) with features `server-api-scram` (SCRAM-SHA-256 via RustCrypto) and extended-query support. SQL parsed with `sqlparser` (`PostgreSqlDialect`) into its AST, then lowered to `LogicalRequest`. Supported statements in v1: `CREATE/ALTER/DROP TABLE` (+ `WITH (spacestorage_type = '<type>', …)`), `INSERT`, `SELECT` (projection, `WHERE` with comparison/`AND`/`OR`/`IN`/`LIKE`, `ORDER BY`, `LIMIT/OFFSET`, `GROUP BY` with `COUNT/SUM/MIN/MAX/AVG`, single-container queries plus 2-way `JOIN` lowered to the engine), `UPDATE`, `DELETE`, `SET/SHOW` (session options), `BEGIN/COMMIT/ROLLBACK` (accepted; single-statement atomicity only until `05`), catalog reads on `spacestorage.containers`, `information_schema.tables`, `pg_catalog` minimum needed by `psql \d`. Type-specific operations via set-returning functions in schema `spacestorage` (e.g. `spacestorage.knn('vectors', $1::vector, 10)`). Binary and text result formats.
- **Rationale**: `pgwire` handles startup, SSL negotiation, SCRAM, simple + extended query, `COPY` framing and error/notice encoding; writing PG v3 by hand is ~3k lines of protocol code with no product value. `sqlparser` is the de-facto pure-Rust SQL parser and also provides the ClickHouse dialect (R6), so one parsing dependency serves two protocols.
- **Alternatives considered**: hand-written v3 protocol (rejected: cost, no benefit); `postgres-protocol` crate (rejected: message codecs only, no server state machine); `datafusion` for SQL execution (rejected: brings its own engine and Arrow type system, violating "no second type system").

## R3. Cassandra CQL native protocol

- **Decision**: CQL binary protocol **v4** (required) and **v5** (negotiated when the client offers it; otherwise fall back to v4 via `PROTOCOL_ERROR` per spec). Frame codec from `cassandra-protocol` (pure Rust, from cdrs-tokio) for `OPTIONS/SUPPORTED/STARTUP/AUTHENTICATE/AUTH_RESPONSE/QUERY/PREPARE/EXECUTE/BATCH/REGISTER/RESULT/ERROR/EVENT`; `PasswordAuthenticator`-compatible SASL PLAIN. CQL text parsed by a **hand-written recursive-descent CQL parser** (`crates/handler-cassandra/src/cql/`) covering `CREATE/ALTER/DROP KEYSPACE|TABLE` (+ `WITH spacestorage_type = '<type>'`), `SELECT/INSERT/UPDATE/DELETE` with `WHERE` on partition/clustering columns, `IF [NOT] EXISTS`, `USING TIMEOUT <duration>` (Scylla-style; accepted as the native per-query timeout), `USING TTL`, `BATCH`, and `system`/`system_schema` virtual tables sufficient for `cqlsh` and drivers' metadata refresh (`system.local`, `system.peers`, `system_schema.keyspaces/tables/columns`). Consistency level from the QUERY/EXECUTE frame flags (native). Timeout also accepted via frame **custom payload** key `spacestorage.timeout`. Session options via `spacestorage.quorum`/`spacestorage.timeout` custom payload on any frame; inspection via `SELECT * FROM system.spacestorage_options`.
- **Rationale**: No pure-Rust CQL *server* crate exists; `cassandra-protocol` gives frame codecs and the consistency enum, leaving only the server state machine. CQL grammar is small and `sqlparser` does not model CQL specifics (partition keys, `USING`, `IF`), so a dedicated parser is cheaper than bending SQL.
- **Alternatives considered**: v3 support (rejected: obsolete drivers); `scylla` crate (client only); implementing v5 only (rejected: many drivers still default to v4).

## R4. Redis RESP protocol

- **Decision**: `redis-protocol` crate (pure Rust) for RESP2 encoding/decoding and RESP3 (`HELLO 3`). Handler implements: connection/auth (`AUTH <user> <pass>`, legacy `AUTH <pass>` → user `default`, `HELLO`, `PING`, `ECHO`, `QUIT`, `CLIENT SETNAME/GETNAME/ID`, `INFO`, `COMMAND` (minimal), `SELECT` (accepted only for index 0; other indices → error, since namespaces are credential-bound); string/KV family (`GET/SET[EX|PX|NX|XX]/MGET/MSET/DEL/EXISTS/INCR/INCRBY/DECR/APPEND/STRLEN/GETDEL/SETNX/EXPIRE/TTL/PERSIST/TYPE/KEYS/SCAN/DBSIZE/FLUSHDB`), hash family (`HSET/HGET/HMGET/HGETALL/HDEL/HEXISTS/HLEN/HKEYS/HVALS/HINCRBY`), and SpaceStorage commands under the module-style prefix `SS.` : `SS.CONTAINERS` (list with type), `SS.CREATE <name> TYPE <type> [opt…]`, `SS.DROP <name>`, `SS.ALTER`, `SS.USE <container>` (switch the connection's target container for native commands; default `redis`), `SS.OPTIONS SET|GET` (session quorum/timeout), `SS.WITH quorum <L> timeout <ms> <command…>` (per-command options), `SS.GET/SS.PUT/SS.DEL <container> <key> [<canonical-bytes>]` (canonical CRUD on any type), `SS.VEC.SEARCH <container> <canonical-query> <k>` and further type-specific verbs generated from the type registry's operation table.
- **Rationale**: RESP framing is trivial but a maintained codec avoids edge cases (inline commands, RESP3 attributes). The `SS.` prefix follows the Redis modules convention that every stock client passes through verbatim. A per-connection **target container** (`SS.USE`) is the least surprising way to satisfy "keys name containers inside the credential's namespace" while keeping plain `GET/SET` working on a default `kv_collection` named `redis`.
- **Alternatives considered**: Redis `SELECT n` as container selector (rejected: numeric indices cannot name containers); `container:key` key encoding (rejected: collides with common app key conventions and violates "no identifier encoded in names"); full command-set parity incl. lists/sets/streams (deferred: lists/sets/sorted-sets map to L2 types arriving with `03`; the registry-driven `SS.` surface covers them until then).

## R5. Elasticsearch REST API

- **Decision**: `axum` router (shared `hyper` 1.x stack from `001`) served per connection inside `Handler::serve`. Implemented endpoints (ES 7.x/8.x compatible responses, `X-Elastic-Product: Elasticsearch` header so 8.x clients accept the server): `GET /` (cluster info), `GET /_cluster/health`, `GET /_cat/indices`, `PUT/GET/HEAD/DELETE /{index}` (+ `settings.index.spacestorage.type` as the type option), `PUT/POST /{index}/_doc/{id}`, `GET /{index}/_doc/{id}`, `DELETE /{index}/_doc/{id}`, `POST /{index}/_update/{id}` (doc merge), `POST /_bulk` and `/{index}/_bulk`, `GET/POST /{index}/_search` with query DSL subset (`match_all`, `match`, `term`, `terms`, `range`, `bool` with `must/should/must_not/filter`, `exists`, `ids`, `prefix`, `wildcard`), `from/size/sort/_source`, `aggs` subset (`terms`, `min/max/sum/avg/value_count`, `stats`), `POST /{index}/_count`, `POST /{index}/_delete_by_query`, `GET /{index}/_mapping` (derived from stored documents), `POST /{index}/_refresh` (no-op success), `_msearch`; type-specific ops under `/{index}/_spacestorage/{op}` (e.g. `_spacestorage/knn`). Unimplemented endpoints → `501` with ES-shaped error body `{"error":{"type":"not_implemented_exception","reason":"…"}}`.
- **Rationale**: Endpoint subset is what stock clients (`elasticsearch-py/js/rs`, Kibana-free `curl` workflows, Logstash/Beats output basics) call in ordinary CRUD/search use; the product header is required by 8.x clients. Query DSL lowers naturally onto `LogicalRequest::Scan { filter, sort, limit }` and `Aggregate`.
- **Alternatives considered**: implementing the full ES surface (rejected: unbounded); returning `200` with empty bodies for unknown endpoints (forbidden by spec edge case).

## R6. ClickHouse — native binary protocol and HTTP interface

- **Decision**: Two handlers, one driver crate. `clickhouse` implements the **native TCP protocol** server side by hand: `Hello`/`Addendum`, `Query` (with `Settings` block, `ClientInfo`, `InterServer` fields parsed and ignored), `Data` blocks (columnar, per-column type strings), `Ping/Pong`, `EndOfStream`, `Exception`, `Progress`, `ProfileInfo`; compression `LZ4` via `lz4_flex` (pure Rust) with the **CityHash128 v1.0.2** checksum implemented in-house (`cityhash102.rs`, ~200 lines) because no pure-Rust crate pins that exact variant; protocol revision `54460` announced (compatible with `clickhouse-client` 22.x+). Native column types in v1: `UInt8..64`, `Int8..64`, `Float32/64`, `String`, `FixedString(N)`, `Date`, `DateTime`, `DateTime64`, `UUID`, `Nullable(T)`, `Array(T)`, `LowCardinality(String)` (read as `String`). `clickhouse-http` is an `axum` router: `GET/POST /` with `query` param or body, `?database=`, `?default_format=`, `FORMAT` clause; formats `TabSeparated[WithNames[AndTypes]]`, `CSV[WithNames]`, `JSON`, `JSONEachRow`, `JSONCompact`, `RowBinary`, `Native` (reusing the native block encoder), `Pretty`; `/ping`, `/replicas_status`, `/?query=SELECT 1` health idioms; `session_id`/`session_timeout` for `SET` persistence; `X-ClickHouse-*` response headers (`Query-Id`, `Format`, `Summary`). SQL via `sqlparser` `ClickHouseDialect`: `CREATE TABLE … ENGINE = SpaceStorage('<type>')` (type option; `ENGINE = MergeTree` and friends accepted and treated as `relational_table`), `INSERT … VALUES|FORMAT`, `SELECT` (same subset as R2 plus `FORMAT` and `SETTINGS`), `ALTER/DROP TABLE`, `SHOW TABLES/DATABASES/CREATE TABLE`, `DESCRIBE`, `system.tables/columns/databases/settings/spacestorage_options`, `SET`. Settings `max_execution_time` (native → timeout) and `spacestorage_quorum`/`spacestorage_timeout`.
- **Rationale**: Clarification Q5 requires both transports. The native protocol is the only path for `clickhouse-client` and most drivers; HTTP is what dashboards and simple tools use. Hand-writing the native protocol is the largest single item in this feature but has no pure-Rust alternative: `clickhouse-rs` is a client and its checksum is a C++ `-sys` crate (Principle I).
- **Alternatives considered**: `clickhouse-rs-cityhash-sys` (rejected: C++); HTTP only (rejected by Q5); `Native` format over HTTP as the only binary path (rejected: still needs the block codec, and native TCP clients would not work).

## R7. S3 REST API

- **Decision**: `axum` router with path-style addressing (`/{bucket}/{key…}`) and optional virtual-host style when `Host` starts with `<bucket>.`; **SigV4** verification implemented with `hmac`+`sha2`+`hex` (RustCrypto), accepting any region/service scope in the `Credential` and comparing signature in constant time; `UNSIGNED-PAYLOAD` and `STREAMING-AWS4-HMAC-SHA256-PAYLOAD` (chunked signing) accepted; presigned URLs (`X-Amz-Signature` query) accepted; SigV2 rejected. Operations in v1: `ListBuckets` (with extension element `<SpaceStorageType>` per bucket), `CreateBucket` (type option header `x-spacestorage-type`), `HeadBucket`, `DeleteBucket`, `ListObjectsV2` (+ V1), `PutObject`, `GetObject` (with `Range`, conditional headers), `HeadObject`, `DeleteObject`, `DeleteObjects`, `CopyObject`, `CreateMultipartUpload`/`UploadPart`/`CompleteMultipartUpload`/`AbortMultipartUpload`/`ListParts`/`ListMultipartUploads`, `GetBucketLocation`, `GetBucketVersioning` (reports Suspended), user metadata `x-amz-meta-*`, `Content-Type`, ETag = MD5 (single) / `md5(md5s)-N` (multipart) via `md-5` crate. XML via `quick-xml`. Type-specific operations via `POST /{bucket}?spacestorage-op=<op>` with canonical body. Unimplemented operations → `501 NotImplemented` S3 error XML.
- **Rationale**: This subset is what `aws s3`, `s3cmd`, `mc`, SDK `PutObject/GetObject/List` workflows, and backup tools use; multipart is required by SC/Story 1 scenario 7. SigV4 is ~300 lines and RustCrypto keeps it pure Rust.
- **Alternatives considered**: `s3s` crate (pure Rust S3 server framework; rejected for v1 because its trait surface is very large, versions move quickly, and it pulls `hyper` 0.14/1.x adapters — revisit when stabilising); accepting unsigned requests (rejected: FR-010 requires the role system to see a credential).

## R8. WebDAV

- **Decision**: `axum` router with custom methods (`PROPFIND`, `PROPPATCH`, `MKCOL`, `COPY`, `MOVE`, `LOCK`, `UNLOCK`, `REPORT`) plus `GET/HEAD/PUT/DELETE/OPTIONS`; **class 1 + class 2** (`DAV: 1, 2`) so macOS Finder, Windows Explorer, `davfs2`, `cadaver`, `rclone`, Nextcloud clients work. Top-level collection under the root = **container** (`object_collection` default; `MKCOL` with header `X-SpaceStorage-Type` for the type option); deeper paths are object keys with `/`-separated hierarchy synthesised from key prefixes. Live properties: `displayname`, `getcontentlength`, `getcontenttype`, `getlastmodified`, `getetag`, `resourcetype`, `supportedlock`, `lockdiscovery`, `quota-available-bytes`/`quota-used-bytes` (from `07` quotas later; `-1` now); dead properties stored as object metadata; SpaceStorage property `{urn:spacestorage}type` on containers. Locks are stored in a per-namespace system container (`ordered_map` named `.webdav_locks`) through the abstract interface so every node sees them (FR-032); timeouts honoured; `If:` header evaluated. Authentication `Basic` (any transport; documented recommendation TLS) and `Digest` (MD5, RFC 2617; needs the interim plaintext secret). Type-specific operations via `REPORT` with body `<spacestorage:op name="knn">…</spacestorage:op>`. XML via `quick-xml`.
- **Rationale**: Class 2 is required for the common desktop clients; storing locks as a normal container is the only way to satisfy "any node coordinates" without a private cluster service.
- **Alternatives considered**: `dav-server` crate (pure Rust; rejected: its filesystem-oriented backend trait does not map to typed containers and pulls its own auth model); class 1 only (rejected: Finder/Explorer refuse read-write mounts without `LOCK`).

## R9. Canonical representation (Clarification Q4)

- **Decision**: One **canonical JSON** document per value, produced by `spacestorage-types::canonical`: UTF-8, no insignificant whitespace, object keys sorted by UTF-16 code units (JCS/RFC 8785 ordering), integers as JSON integers (i64/u64 exact), floats via shortest round-trip repr (`ryu`; NaN/±Inf as strings `"NaN"`, `"Infinity"`, `"-Infinity"`), binary as base64url without padding under `$b`, timestamps as RFC 3339 UTC strings under `$t`, envelope `{"$type":"<type>/<value-kind>","$v":<schema-version>,"$d":<payload>}`. Deterministic: identical logical values → identical bytes. Media type `application/vnd.spacestorage.canonical+json; v=1`. Carriers: PostgreSQL `jsonb`/`text` (and `bytea` = raw UTF-8), Cassandra `text` (or `blob`), Redis bulk string, ClickHouse `String` (also `JSON` column type when the client asks), Elasticsearch JSON value under `_spacestorage` field or raw body, S3 object body with the media type, WebDAV entity body with the media type. Every driver accepts canonical bytes on write for **every** type, including native ones (writing canonical into a native-type container is a valid write). Versioned: `$v` increments on representation changes; drivers accept all documented versions and emit the current one.
- **Rationale**: JSON is the only self-describing text format every one of the seven protocols can carry verbatim (Elasticsearch cannot carry raw bytes; SQL dialects carry text natively). Sorted keys and shortest-round-trip floats make "read through X, write back unchanged through Y" byte-stable (Story 2 scenario 4a).
- **Alternatives considered**: CBOR (`ciborium`) (rejected: not carriable by Elasticsearch without base64 wrapping, which breaks "unaltered"); protocol-idiomatic fallbacks (rejected by Q4); strict RFC 8785 number formatting (adopted for ordering; float formatting uses `ryu` shortest-round-trip which is the JCS algorithm — documented as our normative definition).

## R10. Quorum vocabulary, option syntax, precedence, inspection (Clarifications Q1)

- **Decision**: `QuorumLevel` enum: `ONE | TWO | THREE | QUORUM | LOCAL_QUORUM | EACH_QUORUM | LOCAL_ONE | ALL | Acks(u16)`; parsed case-insensitively from text (`"quorum"`, `"2"`, `"acks=2"`). `QueryOptions { quorum: Sourced<QuorumLevel>, timeout: Sourced<Duration>, namespace, schema, principal, protocol, protocol_version, client_app }` with `Sourced<T> { value, source: Query|Session|NamespaceDefault|GlobalDefault, clamped: Option<ClampReason> }`. Precedence per FR-025. Clamping per FR-030: engine asks `PlacementInfo::replicas(container)`; if `quorum` unsatisfiable and `source ∈ {NamespaceDefault, GlobalDefault}` → clamp to `Acks(replicas)` with `clamped = ReplicaCount{requested, available}`; if `source ∈ {Query, Session}` → `Error::QuorumUnsatisfiable`. Timeout above `query_defaults.max_timeout` → clamp with `ClampReason::MaxTimeout`. Global defaults in config: `query_defaults { write_quorum TWO; read_quorum ONE; timeout 30s; max_timeout 10m; }` (live-reloadable; snapshot taken at query start). Per-protocol syntax is fixed in [contracts/query-options.md](contracts/query-options.md): native fields where they exist (CQL consistency, CQL `USING TIMEOUT`, ES `timeout`/`wait_for_active_shards`, ClickHouse `max_execution_time`), otherwise SQL `SET spacestorage.quorum|timeout` + leading hint comment `/*+ spacestorage: quorum=TWO timeout=5s */`, ClickHouse `SETTINGS spacestorage_quorum=…`, Redis `SS.OPTIONS` / `SS.WITH`, HTTP protocols headers `X-SpaceStorage-Quorum` / `X-SpaceStorage-Timeout` per request and `X-SpaceStorage-Session: quorum=…;timeout=…` to set connection defaults. **Inspection**: HTTP protocols return `X-SpaceStorage-Applied-Quorum`, `X-SpaceStorage-Applied-Timeout`, `X-SpaceStorage-Options-Source` on every response; SQL dialects expose `SHOW spacestorage.options` / `system.spacestorage_options`; Cassandra `system.spacestorage_options`; Redis `SS.OPTIONS GET`. Every executed request is recorded (`ExecutionRecord`) with protocol and applied options (FR-037).
- **Rationale**: Reuses each protocol's idiom so stock clients need no changes; `Sourced<T>` makes source and clamping first-class so inspection and tests are mechanical. Response headers are the only reliable "session inspection" on stateless HTTP protocols.
- **Alternatives considered**: Global-only defaults (rejected by spec); mapping Redis `SELECT n` to quorum (absurd); rejecting all unsatisfiable quorums (rejected by Q1).

## R11. Interim authentication and credential→namespace binding (Clarification Q2, FR-009/FR-010)

- **Decision**: `spacestorage-auth::Authenticator` trait with `authenticate(Credential) -> Result<Principal, AuthError>` where `Credential ∈ { Password{user, secret}, ScramSha256{…}, SigV4{access_key, string_to_sign, signature, scope}, DigestMd5{…}, Token{…} }` and `Principal { name, namespace, schema: "public" default, roles: Vec<String> }`. Interim implementation `UsersFile` reads `auth { users_file <path>; }`: whitespace-separated lines `name secret namespace [schema] [roles,…]`, `#` comments; file mode must be `0600` or stricter on Unix (else startup error `users_file_permissions`); reloaded live. Plaintext secrets are required because SCRAM (server derives the verifier at load), SigV4 (HMAC with the secret) and Digest (MD5 of `user:realm:secret`) all need the secret or a scheme-specific derivative; the file is the single seam `07` replaces with the cluster role store. Namespace binding: for `postgresql`/`clickhouse*`/`cassandra` the client-selected database/keyspace must equal the principal's namespace **or** the principal must have role `admin` (which may select any namespace); for `redis`/`s3`/`webdav`/`elasticsearch` the session namespace is the principal's namespace unconditionally, and a principal without a namespace on those protocols is refused (FR-009a). Namespaces are created implicitly on first reference in this feature (no namespace admin API until `07`).
- **Rationale**: Every protocol's native auth exchange (SCRAM, SASL PLAIN, `AUTH`, Basic/Digest, SigV4, ClickHouse password/`X-ClickHouse-User`) can be served from one principal model. Mirrors `001` R8's approach and its "referenced, never inlined" rule.
- **Alternatives considered**: hashed-only secrets (rejected: SigV4 and Digest are impossible without the secret or a derivative computed at provisioning time; `07` may introduce per-scheme verifiers); anonymous access on loopback (rejected: FR-010).

## R12. Namespace, schema, and container addressing per protocol

- **Decision**: `ContainerRef { namespace, schema, name }`; default schema `public`. PostgreSQL: database → namespace, PG schema → schema (native). ClickHouse: database → namespace; tables live in `public` unless named `schema.table` is unavailable in ClickHouse syntax → ClickHouse addresses only `public` in v1 (documented). Cassandra: keyspace → namespace; tables in `public`. Redis: `SS.USE <container>` in `public`; default container `redis` (`kv_collection`, auto-created on first write). Elasticsearch: index → container in `public`. S3: bucket → container in `public`. WebDAV: first path segment → container in `public`. Names that violate a protocol's rules are exposed via reversible escaping documented per protocol (e.g. S3 bucket names: characters outside `[a-z0-9.-]` percent-hex-escaped as `-xx-`; PG identifiers quoted). Container listing per protocol: `spacestorage.containers` view (PG), `system.tables` with `engine = 'SpaceStorage(<type>)'` (CH), `system_schema.tables` with `extensions['spacestorage_type']` (CQL), `SS.CONTAINERS` (Redis), `GET /_cat/indices?v&h=index,spacestorage.type` and `GET /_spacestorage/containers` (ES), `ListBuckets` with `<SpaceStorageType>` (S3), `PROPFIND /` depth 1 with `{urn:spacestorage}type` (WebDAV). Every listing includes **all** containers regardless of type (FR-013).
- **Rationale**: Uses each protocol's natural concept exactly as the clarification says; a fixed default schema keeps schemaless protocols simple while PG keeps full schema addressing.
- **Alternatives considered**: schema encoded into names for schemaless protocols (rejected: same objection as namespace prefixes); per-credential schema binding (kept as an optional column in the users file, default `public`).

## R13. Type option on native create verbs (Clarification Q3)

- **Decision**: PostgreSQL `CREATE TABLE … WITH (spacestorage_type = 'vector_collection', spacestorage_opt_dims = '768')`; Cassandra `CREATE TABLE … WITH spacestorage_type = 'vector_collection' AND spacestorage_opt_dims = '768'`; ClickHouse `ENGINE = SpaceStorage('vector_collection', dims=768)`; Redis `SS.CREATE vectors TYPE vector_collection dims 768`; Elasticsearch `PUT /vectors {"settings":{"index":{"spacestorage":{"type":"vector_collection","dims":768}}}}`; S3 `PUT /vectors` with headers `x-spacestorage-type: vector_collection`, `x-spacestorage-opt-dims: 768`; WebDAV `MKCOL /vectors` with `X-SpaceStorage-Type: vector_collection`, `X-SpaceStorage-Opt-Dims: 768`. Default type per verb: SQL/CQL table → `relational_table`; ES index → `document_store`; S3 bucket, WebDAV collection → `object_collection`; Redis `SS.CREATE` has no default (type mandatory); the implicit Redis `redis` container is `kv_collection`. Type options are validated by the type registry (`Datatype::validate_create_options`), so drivers never hard-code type knowledge.
- **Rationale**: Each syntax is the protocol's own extensibility point for table/index/bucket options; stock clients pass them through verbatim.
- **Alternatives considered**: a SpaceStorage-only DDL statement on every protocol (rejected: not idiomatic, and PG/CQL/CH clients would need raw-statement escape hatches).

## R14. Protocol mismatch detection (FR-004)

- **Decision**: Every handler reads the first bytes with a 1 s deadline (`tokio::time::timeout`) and validates the protocol signature before allocating session state: PostgreSQL — 4-byte length + protocol code `196608` (3.0), `80877103` (SSLRequest), `80877102` (Cancel), `80877104` (GSSENC → refuse cleanly); Cassandra — first byte version `0x04|0x05` with direction bit clear and opcode `OPTIONS(0x05)|STARTUP(0x01)`; Redis — `*` or `+` or inline ASCII command line; ClickHouse native — varint `0` (`Hello`) followed by client-name string; HTTP handlers (ES, CH-HTTP, S3, WebDAV) — a valid HTTP/1.x request line or HTTP/2 preface (h2c preface refused with `HTTP/1.1 505`). On mismatch: send the protocol's own refusal where the protocol has one (PG `ErrorResponse` `08P01`, CQL `ERROR PROTOCOL_ERROR`, RESP `-ERR unknown protocol`, HTTP `400` with `text/plain` body, ClickHouse `Exception`), log `protocol_mismatch{entrypoint, handler, first_bytes_hex}`, increment `handshake_rejected_total{protocol, reason="mismatch"}`, close.
- **Rationale**: Cheap, deterministic, satisfies "within one second" and keeps a misdirected client from hanging.
- **Alternatives considered**: auto-detecting and forwarding to the right handler (rejected: violates one-protocol-per-port).

## R15. Execution boundary IR (`LogicalRequest`) and interim `LocalEngine`

- **Decision**: `LogicalRequest` is a protocol-neutral enum in `spacestorage-exec`: `Ddl { CreateContainer{ref, type, options}, AlterContainer, DropContainer, ListContainers, DescribeContainer }`, `Point { Get, Put, Delete, Exists, Incr, Expire }` (KV/hash/object semantics with `Key`), `Scan { container, projection, filter: Expr, sort, limit, offset }`, `Aggregate { container, group_by, aggs, filter }`, `Join { left: Scan, right: Scan, on, kind }` (2-way in v1), `Mutate { Insert{rows}, Update{set, filter}, DeleteWhere{filter} }`, `TypeOp { container, op_name, canonical_args }` (registry-defined operations such as `knn`), `Object { Put{stream}, Get{range}, Head, Copy, Move, ListPrefix{delimiter}, MultipartBegin/Part/Complete/Abort }`, `Batch(Vec<LogicalRequest>)`. `Expr` is a small typed expression tree (`Eq/Ne/Lt/Le/Gt/Ge/In/Like/Prefix/Range/And/Or/Not/Exists/IsNull`, field paths, literals as `CanonicalValue`). `QueryEngine::execute(req, opts) -> BoxStream<ExecutionEvent>` where events are `Schema`, `Rows(Batch)`, `Progress`, `Done{stats}`, `Error`. Drivers convert their AST/verbs into `LogicalRequest` and render events in their wire format. Interim `LocalEngine`: executes directly against `TypeRegistry` containers on the local node, single-replica (`PlacementInfo::replicas = 1`), timeout enforced via `tokio::time::timeout` around the stream, records `ExecutionRecord { protocol, principal, namespace, request_kind, applied_options, duration, outcome }` into a bounded ring buffer readable via `admin` op `executions` (test hook + operator aid). Unsupported combinations → `ExecError::NotSupported{what}` before any mutation.
- **Rationale**: FR-035/FR-036 need one IR that seven different front-ends can lower into; keeping it small (no full relational algebra) is enough for the v1 statement subsets and gives `05` a concrete target to extend rather than replace.
- **Alternatives considered**: `sqlparser` AST as the IR (rejected: SQL-shaped, cannot express Redis/S3/WebDAV ops); Substrait (rejected: heavyweight, relational-only, extra dependency).

## R16. Abstract datatype interface and interim type inventory

- **Decision**: `spacestorage-types` crate: `TypeRegistry { types: BTreeMap<TypeName, Arc<dyn Datatype>> }`; `trait Datatype { name; level (L0–L4); validate_create_options; open(ContainerMeta) -> Arc<dyn Container>; operations() -> &[OperationSpec] /* name, arg schema, result schema */ ; canonical_schema() }`; `trait Container { meta; get/put/delete/exists (Key, CanonicalValue); scan(filter, sort, limit) -> stream; aggregate; type_op(name, args) -> CanonicalValue; object_* for byte-stream types; alter(options); stats() }`. Interim inventory: `kv_collection` (string/hash values with TTL), `relational_table` (rows with declared columns, PK index, simple secondary filters), `document_store` (JSON docs by id, field-path filters), `object_collection` (byte objects with metadata, prefix listing, multipart assembly, range reads), `vector_collection` (f32 vectors + payload, brute-force `knn` with cosine/L2 — no HNSW until `03`), `ordered_map` (range scans; used for WebDAV locks). All in-memory in this feature (feature `03` adds L0 storage primitives and persistence); memory accounted in a registered buffer `types.memory` (Reject policy) using `001`'s `BufferRegistry` (FR-043 of `001`). Registry-driven driver behaviour: listing, create-option validation, operation dispatch, and canonical schema all come from the registry so adding a type never touches a driver (Story 2 scenario 11; startup mapping check FR-018 becomes "every type in registry has a carrier mapping in every declared driver", which is structural and always true for canonical fallback — a driver additionally declares its *native* mappings).
- **Rationale**: Six types cover every protocol's default type plus at least one foreign type per protocol for the conformance suite, without pre-empting `03`'s inventory.
- **Alternatives considered**: waiting for `03` (rejected, R1); persisting via `sled`/`redb` now (rejected: storage engine is `03`'s L0 decision).

## R17. Metrics reserved for `08`

- **Decision**: Names follow `001` R13 style and `08`'s "API metrics"/"User communication" label sets: `spacestorage_protocol_connections_total{protocol,namespace}`, `spacestorage_protocol_connections_active{protocol,namespace}`, `spacestorage_protocol_handshake_rejected_total{protocol,reason}`, `spacestorage_protocol_requests_total{protocol,namespace,user,app,kind}`, `spacestorage_protocol_request_errors_total{protocol,namespace,user,app,error_type}` with `error_type ∈ {protocol, auth, authz, not_supported, timeout, quorum_unsatisfiable, invalid_value, internal}`, `spacestorage_protocol_request_duration_seconds{protocol,namespace,kind}` (histogram), `spacestorage_protocol_bytes_read_total` / `_written_total{protocol,namespace}`, `spacestorage_query_options_clamped_total{protocol,reason}`. Tracked in `node::stats` as atomics/histogram buckets; exposition by `08`.
- **Rationale**: FR-042 lists exactly these figures; using `08`'s label names avoids a later rename (Observability Contract).
- **Alternatives considered**: per-driver ad-hoc counters (rejected: inconsistent labels).

## R18. Testing strategy and "stock clients"

- **Decision**: Three layers. (1) Unit tests per crate (parsers, codecs, canonical JSON determinism, SigV4 vectors from the AWS test suite, CityHash102 vectors from ClickHouse). (2) **Conformance suite** `crates/conformance/` (Rust integration tests) that boots a node in-process with all eight handlers on ephemeral ports and drives it with pure-Rust stock client crates as the "unmodified clients": `tokio-postgres`, `scylla` (CQL v4), `redis`, `elasticsearch`, `clickhouse` (native, by the `clickhouse` crate) + `reqwest` (CH HTTP), `aws-sdk-s3` (with `behavior-version-latest`, path-style, static credentials), `reqwest_dav`; it runs the SC-001 smoke workflow per handler, the SC-002/SC-003 type matrix (every type × every protocol × create/list/read/write/alter/drop, canonical round-trip, write-back-unchanged), SC-004 option recording via the `executions` admin op, SC-005 timeout, SC-006 cross-protocol equivalent queries, SC-008 mismatch matrix (every client against every other handler's port), and SC-007 on a 2-node in-process cluster **once `04`/`06` exist** (marked `#[ignore]` with reason until then). (3) `quickstart.md` uses the real CLI tools (`psql`, `cqlsh`, `redis-cli`, `curl`, `clickhouse-client`, `aws`, `cadaver`) for manual verification. Client crates are `dev-dependencies` only; some (e.g. `aws-sdk-s3`) pull `aws-lc-rs`/`ring` — acceptable in dev-deps since Principle I governs the shipped server.
- **Rationale**: Pure-Rust client crates give reproducible CI without external binaries; the CLI-tool quickstart proves the "unmodified stock client" claim with the tools users actually run.
- **Alternatives considered**: Docker-based client containers in CI (deferred: heavier; useful later for version-matrix testing).
